# Workspace chats — which agent chat ran in which workspace

The sidebar answers "which chat did I work with on this branch". That question
cannot be answered from the agent's own on-disk store, which is keyed by the
directory the agent was launched in: a branch checkout very often is not that
directory. **Measured 2026-07-30 against a live session:** 9 of 14 workspaces
resolved to no chats that way, and 4 of the 9 sessions herdr was actively wired
to lived under a different directory than their workspace.

The live wiring (`agent_session` on a pane) knows the truth, but only while the
pane exists — closing a tab erases it, and the question is asked in the past
tense. So the association is recorded as it happens, in an append-only ledger at
`~/.config/herdr/workspace-chats.json`.

Deliberately **outside** the session snapshot: that snapshot describes the LIVE
layout and the restore contract depends on its shape, while this ledger is
history that outlives the workspaces it describes.

Design and the measurements behind it:
`.local/prd/2026-07-30-spaces-branch-chat-drawer-PRD.md`.

## Completeness — where the drawer's rows come from

The ledger alone was not enough, and the measurement said so plainly. On
2026-07-30 the fourteen open workspaces held **1510** transcripts between them
in the agent's own store; the ledger knew **14**, because it only began
recording the day it was written. A ledger-only drawer showed almost nothing —
one workspace with 1225 transcripts showed two rows.

The reverse is also true and is why the ledger cannot simply be replaced: a
chat that started in one directory and moved is filed under the directory it
started in. One worktree held 1 transcript in its own directory and 4 in the
ledger. Neither source answers the question alone, so the drawer is their union.

### Cost

Reading the store costs one `read_dir` plus metadata per workspace. Transcripts
are ranked by mtime from that metadata alone and only the newest few are opened.
A file whose (mtime, size) has not moved is not opened at all; one that grew is
read from where the last read stopped (TP-CHATSYNC-01). The cache this replaced
re-read a changed file whole — and a live agent's transcript changes on every
message, so every refresh re-read exactly the biggest files. The merge rides the
debounced session save, never a frame, and reports its own time as
`chat_sync.merge` in the render profile (see "Store cost" below).
| TP-CHATROW-ID-01 | Every laid-out chat row — workspace drawer, daily section, container — carries the chat's `session_id` instead of a list position, resolved at compute time while the rect and the ledger still agree. A press opens exactly the chat the user saw (`open_*_chat` take the id; a chat that left the ledger is a no-op), and the renderer paints each row by the same identity, so a ledger that gains a row between two frames can neither open nor title the wrong chat. The mobile drawer bridges by resolving the id at the press site until its targets carry identity themselves. | The old rects carried `chat_idx`; the ledger is rewritten newest-first while frames are in flight, and an index resolved against the new list opened whichever chat had shifted into the slot — the "wrong chat in the wrong directory" family (#46's sibling), triggered by nothing more than another client filing a chat. | `a_stale_daily_row_press_opens_the_chat_the_user_saw`, `a_click_on_a_daily_row_that_no_longer_exists_does_nothing`, `a_daily_chat_resumes_in_the_daily_directory`, `a_filed_chat_in_a_bucket_resumes_in_its_repository` |
| TP-CHATROW-ID-02 | The laid-out chat-row areas resolve their `session_id` from the SAME ledger every other drawer surface reads — `workspace_chat_rows_for`, keyed by the checkout (TP-WSID-03) — never from the birthplace `identity_cwd` key. | The live incident, verbatim from the user's screen: a worktree-backed workspace badged "14" chats drew ONE and left a region of blank rows — compute measured rows out of one ledger and resolved identities out of another, so the rows existed, consumed height, and could never be found to draw. | `chat_row_areas_read_the_ledger_the_drawer_reads` |

## Store cost (`src/claude_sessions.rs`, `src/codex_sessions.rs`)

The merge runs on the app thread on every session save that folds a new or
stale sighting into the ledger — with a live agent that is every save after a
minute (`SIGHTING_FRESH_FOR_MS`), and every pane birth or death schedules one.
**Measured 2026-10-17 on the reporting machine:** the live agents' transcripts
stood at 96, 176 and 210 MB and were re-read whole on every such save, and the
by-id road probed 693 project directories for each of 374 re-homed chats; the
loop froze 5–7 s after every pane birth or death (an eu-stack profile of one
self-triggered freeze put 32 of 35 busy samples in this merge). herdr-web's agent
start gave up inside that freeze and closed a tab whose start then succeeded.

The fold trusts what it already read only while the file is the same file
(identity), at least as long (size) and still holds the bytes it ended on
(anchor). Claude Code only appends; a tool that edited a line in the middle of a
transcript without changing its length or the fold's last bytes would not be
seen until the file is next read whole — a known limit, not a promise.
